# B站关注视频提醒（Edge 扩展）

## 安装

1. 当前扩展文件夹为 `D:\BiliPush-Edge-Extension`，请保留整个文件夹，不要只移动其中某个文件。
2. 在 Edge 地址栏打开 `edge://extensions/`，开启“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的这个文件夹。
4. 在同一个 Edge 配置文件中登录 https://www.bilibili.com/ 。
5. 点击工具栏里的扩展图标，打开中文设置面板；点击“立即检查”，确认账号及建立基线。
6. 点击“测试系统通知”，确认 Windows 能显示提醒。第一次检查不会通知已有视频。

扩展图标就是设置入口，也可从 Edge 扩展详情页打开“扩展选项”。加载扩展后请保留文件夹；修改文件后在扩展管理页点击“重新加载”，并关闭旧设置页，重新点击扩展图标打开。

## 设置

- 默认每 3 分钟检查一次，可设为 1～60 分钟。
- 默认每轮最多读取 5 页，可设为 1～10 页。遇到已有视频记录通常会提前结束。长时间离线或关注量很大时，页数上限之外的投稿可能遗漏，面板会给出提示。
- 默认提醒所有关注 UP 主；可改成指定 UID 白名单。白名单只能筛选关注流，不能订阅未关注的 UP 主。
- 支持暂停、静音、立即检查、测试通知及最近 100 条检测记录。
- “立即检查”即使暂停也会执行一次，并更新已检查记录、发送符合条件的新视频通知。测试通知始终尝试带声音，实际由系统控制。
- 设置修改后需要保存。改变筛选范围不会补发此前已检查的视频。

## Cookie 和数据

后台 `fetch` 使用 `credentials: 'include'`，由 Edge 自动携带此配置文件中适用的 B站 Cookie。没有手动粘贴 Cookie 的入口，也不读取 Cookie 值或将其写入扩展存储。不申请 cookies、浏览历史或全站访问权限。

仅向 `https://api.bilibili.com` 请求当前登录状态和关注视频流。设置、账号 UID/昵称、视频编号、最近记录和待发送队列保存在当前浏览器的本地扩展存储，不上传到第三方。点击视频后打开 B站页面。

不同 Edge 配置文件互相独立。切换 B站账号后，下次成功检查会重建基线。退出登录或接口验证失败会显示错误并退避重试，最多间隔 60 分钟；重新登录后可点击“立即检查”。

## 运行条件与限制

不需要一直打开 B站标签页，但需要 Edge 进程运行。如希望关闭窗口后继续工作，请在 Edge“系统和性能”中检查“关闭 Microsoft Edge 后继续运行后台扩展和应用”设置；实际后台运行需在本机验证。完全退出浏览器、关机或休眠期间不能持续查询，恢复后只能在分页上限内补查。

这是一种定时查询提醒，并非 B站服务器提供的实时推送。只处理关注流里的 `DYNAMIC_TYPE_AV` 原创视频动态，不提醒转发、纯文字动态、直播或番剧。数据来源不属于稳定的官方开放接口，可能受登录状态、风控和接口变化影响。当前实现不会尝试绕过验证；遇到失败请在 B站网页检查登录与验证状态。

通知横幅、提示音、保存时长均受 Windows 和 Edge 设置影响。待发送队列先落盘再通知；如浏览器恰好在通知显示与确认落盘之间退出，恢复后同一通知可能再出现。

## 实现参考

对用户提供的 Bilibili-Cedar 发行目录进行只读检查：可见 Python 插件、打包模块字符串及历史启动日志表明，它使用登录 Cookie 查询关注动态流，定时分页写入数据库，再按照订阅游标通过 OneBot 推送。历史日志显示当时使用 600 秒轮询、2 页拉取；这不是对其当前运行配置的确认。

本扩展独立编写，沿用“关注流查询与去重”的思路，没有复制 Cedar 的代码、数据库或登录信息，也不需要运行 Cedar。
