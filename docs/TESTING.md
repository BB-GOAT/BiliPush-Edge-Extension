# 验证与回归

## 自动检查

在仓库根目录运行 `node scripts/check.mjs`（或 `npm run check`），无需安装依赖。检查包含 manifest/版本字段一致性、权限清单、引用路径存在性、全部维护脚本语法和 `tests/regression.mjs`。

回归脚本使用内存模拟的 Chrome API 与 B站响应，没有读取本机 Cookie、没有发送真实网络请求、没有写入真实浏览器存储，也不会弹出系统通知。覆盖设置归一化、AV 解析、首次基线、分页/去重/异常游标、账号切换、UID 筛选、暂停、失败退避、待发送恢复、消息来源边界、关注列表分页和三类测试通知的点击行为。

回归用例使用相对路径，不依赖 `D:` 安装位置。修改后用明确的行为断言检验结果，避免只验证实现中调用了某个函数。接口样例应先脱敏，不提交 Cookie、真实用户 UID、关注列表或完整响应转储。

## Edge 人工回归

1. 在扩展管理页重新加载，确认没有 service worker 注册或脚本错误。关闭旧设置页，从扩展图标重新打开。
2. 确认检查间隔、提醒范围等原有设置仍然存在；账号、上次成功时间和历史列表可以显示。
3. 点击“立即检查”，确认当前账号正确，能获取关注视频，失败时有具体错误而非一直等待。
4. 连续点两次「测试投稿」验证最新视频样式和链接。点「测试动态」确认能看到最新非投稿动态，点击打开原动态。点「测试直播」确认能打开当前正在直播的关注主播房间；若无人开播，发送演示通知并确认点击返回设置页。
5. 修改检查间隔并保存，确认下次检查时间随之变化；恢复用户原设置。
6. 验证暂停后没有自动任务，恢复后再次安排任务；不要误把暂停期间的手动检查视为禁用。
7. 选「仅指定的已关注 UP 主」并打开选择面板，确认旧名单可见。尝试搜索第二页以后的关注、仅看已选、切换类别、取消，再分别勾选三类名单。确认后先检查人数，再保存并重新打开设置验证。允许直播接口后立即检查，首次开启只建立基线。
8. 等下一次定时检查，观察真实新投稿、非投稿动态或新开播是否只提醒一次，点击分别到达对应页面。同个房间持续直播不重复提醒，下播被检测到后再次开播能提醒。重启 Edge 后应继续沿用已有基线。

只验证本次修改需要的场景。实际等待新视频、切换账号、重启/休眠等检查由用户合适时完成；未做的项目必须如实记录。
